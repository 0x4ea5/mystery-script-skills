# 剧本杀分角色模拟

保留旧调用名，职责收窄为主持准备和实际模拟。交付发放账、真实独立首答、自由接话、提示与裁定、阶段认知和配音交接；只完成用户授权的阶段，单局玩法变体留在项目配置。

## 接上资料

先核当前索引、版本及续做状态。原件或关键页未可靠归档时，用 [mystery-script-ocr](../mystery-script-ocr/SKILL.md) 补相应缺口；已有可靠档案直接复用。用户明确要从原件到音频的整套工作，就依次衔接三阶段，不以介绍流程代替执行。

准备本幕时读 [主持依据](references/dm-preparation.md)，核发放、停止点、验收与认知边界。原文、手册解析、勘误、推论、补足和未知分开；当前阶段解法不能用终局真相反判。

## 实际运行

按 [分角色运行](references/simulation.md) 委派独立实例：默认DM和六名空白上下文玩家，人数依作品与用户要求。并发不足时分批唤醒同一组身份；原件准备、下一幕资料及已完成阶段的音频可并行。协调者不能代写六份发言称独立模拟。

DM 实例加载 [mystery-dm](../mystery-dm/SKILL.md)，以保障玩家游戏体验、让游戏进行下去为首要职责，按桌面需要管理节奏、参与、扶车和转场；每名玩家实例加载 [mystery-player](../mystery-player/SKILL.md)，在各自私区持续维护本桌的 `记忆.md`。续局先恢复本人缓存及漏读事件，换幕前保存；只收更新回执，不把私人缓存自动公开。协调者向玩家发放该玩家技能和明确允许文件，不把主持技能、全局检索范围或其他玩家路径一并交给玩家。

玩家只获自己的已发材料和当时公开内容。文件名、目录、标题、元数据及邻卡也核剧透，主持全知区独立；提示约束不冒充文件系统强隔离。

需要独立首答时收齐后才公开，之后自由短句接话。主持根据体验和推进需要组织场景、规则、发放、参与、节奏及裁定；有效讨论时给空间，玩家持续掉队或卡关时主动帮助，不反复要求长总结、不按固定轮数凑对白。观众向录制再读 [讨论节奏](references/audience-simulation.md)。

原作规定演绎、私读和玩家自由意见分别执行、分别标记。制作漏发/误读不算推理错误。缺关键证据保留未知，不为音频进度制造通过。

## 姓名和记录

内部座位ID、实例及声线映射固定；显示称呼按本人公开的最新认知变化，未知、姓氏候选、暂认、阶段已验分开。别人的推测、私读回执或主持答案不提前替本人改名。记声明原句、生效位置，历史发言不回填终局姓名；声音性别不作角色身份依据。采用桌外昵称须标清是玩家称呼。

原提交及公开事件保留版本、哈希和顺序。准备、派发、收到、公开、裁定分别记，补记时间不冒充交付时间；用 [续做记录](references/checkpoint.md) 记真实完成范围、待收与下一步。

## 交给配音

用户授权后按 [音频交接](references/audio-handoff.md) 移交 [local-dialogue-audio](../local-dialogue-audio/SKILL.md)：冻结讨论、来源、发放停止点、原作演绎标识、逐发言显示名与段类型。已完成幕可先配音；GPU按显存和实测吞吐调度互不重叠的任务，不固定禁止并行，也不让多进程争写同一状态或缓存。

到实际终局或明确停点才验收模拟范围，提供可编辑本地入口。AI模拟和技术检查不称真人体验或全程听校。各项目的位置、版本和历史停点以本项目索引及续做记录为准，不沿用其他作品的数量或规则。
